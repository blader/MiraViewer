F3 ownership checkpoint: the initial copy-on-write design assumed that downstream heavy-operation preparation would always precede any retained label read. A direct callback regression disproved that assumption: requesting original detail, then editing again before the callback prepared its work, changed the callback's input. Keep the single editing owner, but borrow its current revision at the callback handoff itself. The alternative of copying every published mask preserves implicit snapshot semantics but retains the original per-stroke cost. Ordinary displays consume versioned views; history retains immutable patches; asynchronous readers receive borrowed revisions; storage captures its payload before yielding. A further legitimate reader that cannot obey this contract would reopen the representation decision, not justify an unrelated cache guard. The retained failing reproduction is `frontend/tmp/sparse-editing-borrow-handoff-before.log`; the corrected regression and acceptance below passed.

### F5 scalable-backup continuation: contract and architecture

The preceding turn made concrete progress: PR #12 merged as `d4fb10fdfbf2d1e9aac44759eb2387ce1e5ba477`. Its measurements and private/failed receipts remain intact. The next work starts from that merge on `blader/siqi-chen/audit-streaming-backups`; no old bundle or acceptance run is restarted merely because the branch changed.

**Required result:** a backup larger than 512 MiB must export and restore exact scans, saved labels, hard marks, panel/acquisition settings, models and derived frames with bounded live buffers. Verified restoration is staged durably but remains invisible until one noninterruptible publication transaction. Corruption, quota failure and cancellation before that boundary must preserve every previously visible record, including model bytes. Legacy version-2 backups and legacy cached models remain readable. Browser evidence must use real generated bytes, record peak memory and exercise failure/cancellation, not only virtual sizes or a passing manifest calculation.

**Structural mismatch:** export retains whole payload buffers and JSZip output; restore retains every verified payload and writes a separate model database before the medical transaction. Raising a constant cannot fix either boundary. Cross-database rollback would add a second publication authority and can fail during recovery. A dataset-generation rewrite could make publication a pointer swap but would force unrelated medical readers/writers through a new addressing layer. Instead, retain existing medical stores and move the model API to a store in the same database, with one-time transactional legacy migration. Stage verified rows/chunks under operation-owned keys and publish from that staging store in the existing medical transaction.

**Export/read path:** retain the versioned manifest and ZIP safety policy; remove eager JSZip payload accumulation. Read and hash bounded chunks, preserve SHA-256 and CRC integrity, and provide a streaming destination while keeping the ordinary download path usable. The later browser proof must distinguish file-backed Blob references from actual JavaScript/RSS growth; a renamed buffered exporter is not completion. The [incremental SHA-256 API](https://github.com/paulmillr/noble-hashes#implementations) is a candidate for retaining digest verification without whole-payload WebCrypto buffers; adopting it requires ordinary dependency and known-vector checks.

**Execution and falsifiers:** first prove model/medical atomicity with a late-write failure and legacy-cache migration; then stage bounded payloads and remove aggregate materialization; then validate true above-cap export/restore, failure preservation and memory in the built app. If staged publication itself retains payload-sized buffers or cache migration creates a second visible model authority, reopen this design before adding guards. One heavyweight validation runs at a time. Existing unit/browser evidence is retained at its own fingerprint; final whole-suite and browser verification wait for the implementation boundary to settle. No F5 completion is claimed by this plan.

### Important details

**Source-owned settings.** Safe legacy rows are projected in memory during readonly hydration, not migrated by reads. The first intentional canonical save preserves legacy provenance; ambiguous rows still require explicit assignment. Unrelated imports do not replace the current patient's manual adjustments or browsing progress. Restore/recreation rotates the saved-work token, retiring old callbacks and rejecting queued/cross-tab writers atomically.

**Heavy-operation ownership.** Reconstruction, refinement, enhancement, selection, custom inference and model-file replacement all prepare through the imaging context. The caller's retained editing snapshot is counted as a floor, not added again to the current editor. The admitted runtime estimate is passed unchanged to the tracking owner; subsequent compressed prompts cannot lower it. Custom workers terminate on result, error, abort or deadline and are never retained. EfficientTAM sessions may be retained for 30 seconds, but each job gets fresh history and channel state.

**Exact versus blended display.** Exact mode is calibrated at the source plane, not a claim that the whole volume render is diagnostically calibrated. Unsupported samples remain absent, nearer opaque anatomy may occlude, and a selected contour can overlay the plane. Blend mode deliberately changes luminance for anatomical context. Invalid source identity clears content; an ordinary same-source decode failure preserves the last good plane with a notice.

**Memory evidence.** The new 128³ synthetic oracle contains 20 MiB of real weights used by a data-dependent Gather, not filler metadata or an unused initializer. It proves this model's execution and output, not arbitrary model complexity. Chromium memory dumps sample the worker-host renderer, including its page. They are neither isolated worker allocation nor a guaranteed instantaneous/OS-release peak. The admission policy is not an allocator cap.
